## Determinism model
- 2026-09-07 PLAYER START (KNOWN, notes/player_start_randomness.md): Tplayer.x/y are written by new_game as constants 200.0/431.0 right after reset_player, on both fresh-game and replay paths; no PRNG involved. Operator-observed variation must be the surrounding floor geometry (seed), the profile start_floor option, or early input; open.
- 2026-09-07 LAYOUT (KNOWN, notes/layout_determinism.md, artifacts/rand_call_sites.json): floor k = f(Treplay.random_seed, k, the five difficulty fields in the same header); add_floor consumes 0/1/2 rand() per floor decided by its own floor counter and floor_shrink/floor_size, never by ticks/QPC/prior rand values; called 30× from new_game and on demand from play() as the player climbs (when, not what, depends on timing). Corrections: only the FIRST new_game per process does srand(time)→rand→srand; later new_game calls reuse demo->random_seed (same tower within a session — to be confirmed by a player). A second PRNG new_rand/new_srand (state 0x4ff108, 18 sites) is cosmetic only (particles, sounds, taunts, blit jitter). create_post and stars.c are dead code; ad selection runs only in the main menu.
- 2026-09-07 LIMITATION (KNOWN): the per-tick digest of game-owned globals includes pointer values into the heap arena, so changing the allocator changed the digest stream from tick 126 while staying self-consistent (two runs EQUAL). Digest streams are comparable only across runs of the same carrier build; cross-build comparisons need a pointer-normalized domain (future). All proofs in the ledger were made within one build.
- 2026-09-07: human-keyboard record/replay CLOSED for the key channel (divergence 005 fix below): both providers hand events over at the SAME point - the first Sleep call of a carrier tick - and a recording logs only what the carrier itself handed over, so stamp == delivery tick by construction. Proven with genuine SendInput sessions through the real DirectInput path (carrier/scripts/sendinput_session.py): EQUAL over 1442 and 1914 ticks. Consequence for the framework: an input coordinate must name the delivery POINT, not just the tick - a tick that contains N host wait calls has N distinguishable handover slots, and only one of them is on the same side of the guest's own tick boundary. Also: pre-fix recordings are invalid.
- 2026-09-07: the deterministic heap is a real allocator (first fit + coalescing) whose entire state lives inside the fixed arena region, so snapshot/restore captures the allocator for free and the snapshot is bounded by peak LIVE bytes, not by allocation volume (90 MB -> 29 MB). Consequence for the framework: put allocator metadata in the guest-visible arena, never in host-side statics.
- 2026-09-07 FOLLOW-UP: det mode pins time() to a constant epoch, so every recording/replay shares one tower layout (seed = rand() after srand(time)). Correct rule per §4a: record the observed time()/clock values as events in record mode and replay them, so interactive sessions vary while replays stay exact. Visible check: a --det replay must show the same tower as its recording.
- 2026-09-07: input source is exclusive (`--input=real|script|none`); real+script refused; violations counted (0 in all runs). Recording round trip through the real DirectInput entry point (synthetic) replays EQUAL over 876 ticks. Found while doing it: key_dinput_handle_scancode receives raw DIK codes, not Allegro codes (KNOWN, from _hw_to_mycode bytes). scripts/play.py provides the operator path (record/replay). Human-keyboard recording not yet exercised by a person.
- 2026-09-07 IMPLEMENTED (KNOWN by measurement): virtual clock driven from the main thread's Sleep wrapper; the two Allegro timer threads are never created (_beginthread wrapper by entry address) and _handle_timer_tick is called synchronously; QPC/timeGetTime/time/clock return virtual values; input injected through Allegro's _handle_key_press/_release at tick T; real keyboard parked via a hardware breakpoint on key_dinput_handle_scancode; malloc family → fixed-address bump arena at 0x20000000. - 2026-09-07 FINDING (KNOWN): hashing raw .data+.bss never converges even with a deterministic heap: ~20–30 Allegro/CRT/DirectX globals hold host object identities (COM pointers, HANDLEs, HWND) that vary per process. ## Snapshot model
- 2026-09-07 IMPLEMENTED (KNOWN by measurement, carrier/NOTES.md 'Milestones 8-9'): snapshot at the tick safepoint = main-thread CONTEXT (incl. x87 CW 0x037F) + full .data/.bss + heap arena + live guest stack + carrier state (virtual clock, tick, script cursor, key queue, sensor counters, pinned RNG). In-process rewind certified: post-rewind ticks 400..699 EQUAL to the pre-rewind pass, post-rewind suffix 400..1000 EQUAL to an independent cold run (re-verified by the supervisor against a cold run from before the snapshot code existed), fn-sensor stream EQUAL; --restore-fault named at the restore tick. Capture/restore ~1.6 s; 90 MB of which 99.6 % is the leak-only arena. Cross-process restore FAILS by design evidence: host pointers (DirectDraw surfaces, DirectInput COM) inside .bss and arena-resident BITMAP structs → needs a logical-handle layer or headless mode (§9 rule discharged with evidence). File I/O measured: zero file imports inside play()'s tick window → no logical file table needed. RNG pinned (msvcrt LCG, 5000/5000 match). Trace window: 2000 instructions from a restore with names. pf_inspect.py diffs snapshots by named global.
- 2026-09-07: HYPOTHESIS in win32_pilot.md §6. Nothing implemented. Evidence so far supports in-process rewind: guest globals + arena + guest stack + main-thread CONTEXT at the safepoint; rand() state lives in msvcrt (host) and must be externalized by pinning the LCG in the carrier.

## First-divergence investigations
- 006 (2026-09-07) clean line_intersect vs ORIGINAL, offline: ~950/20000 vectors differed across ALL toolchains (not precision). Root cause: the original's `fucom; test $0x45,%ah; je` idiom only branches on the ordered case, so NaN ua/ub (D==0 with zero numerator) fall through all guards, fistp yields the integer indefinite and EAX=1; the clean `if (!(ua >= 0.0)) return 0;` rejected NaN. Fix: `if (ua < 0.0)`. After the fix: GCC `-mfpmath=387 -mno-sse2 -O2` EQUAL 0/20000 on 4 seeds; MSVC differs only in the 33–49 precision cases. Lesson: hand-written comparisons must reproduce x87 unordered semantics; the oracle caught it.
- 005 (2026-09-07) human recording third_human (581 events, 1735 gameplay ticks, recorded after the tick-boundary capture fix, clean exit): replay starts gameplay at T=248 vs recorded 249. Experiments: (a) scripted newgame at --pace=real vs --pace=fast → EQUAL (pace is not the cause); (b) all events shifted +1 → first 51 gameplay ticks EQUAL, first difference at T=300; (c) only the menu ENTER events shifted +1 → still 248 vs 249. So the recorder's stamp and the replay's delivery coordinate disagree in a way that is not a constant offset. Needs instrumented side-by-side runs (log virtual T, safepoint tick index, cycle_count at every stamp/delivery in both modes). Queued behind the snapshot task (same file).
- 005 FIX (2026-09-07, KNOWN by measurement via the new `--trace-input`, carrier/NOTES.md 'Divergences 004 and 005'): ROOT CAUSE = T was never the whole coordinate. The guest's idle loops call rest(1), so det_wrap_Sleep runs ~10x per carrier tick (4000 Sleep calls / 400 ticks) and the guest's own 20 ms tick (cycle_count 0x506938) is incremented at sub-tick position 0, inside _handle_timer_tick, before the handover in that same Sleep call; play() consumes it as soon as that call returns. Script events could only ever be handed over at sub=0, while the real-key drain ran on EVERY Sleep call, so a human key captured at an arbitrary instant (measured: sub uniformly spread over 0..9) was stamped T but acted on at game tick T+1 — and replayed at game tick T. Negative control: DET_INPUT_DELIVER_SUB=k shows k=0 reproduces the G1 baseline byte for byte while k=1/5/9 all differ from it at the first digest line and agree with each other. Fix: drain real events only at the FIRST Sleep call of a new tick, the same point deliver_due_input uses; and record ONLY the events the carrier itself handed over (Allegro's own key-repeat calls _handle_key_press from _handle_timer_tick at arbitrary sub, 240 ms after the press, and was being recorded as if it were input). Proof: genuine SendInput sessions through the real DirectInput path at --pace=real (SendInput DOES reach this build's key_dinput_handle_scancode), recorded then replayed with --input=script — EQUAL over 1442 ticks / 403 events and over 1914 ticks / 524 events (two more EQUAL at 1421 and 801 ticks). CONSEQUENCE: recordings made before this fix (replays/first_human, second_human, third_human) are INVALID and cannot replay bit-exactly — the per-event sub-position they depended on was never recorded, so no uniform shift repairs them. RESIDUE (open): 4 of 8 sessions diverged, always ones where the desktop repeatedly stole the foreground; record and replay agreed exactly on the pinned RNG (state+calls) and every arena statistic, and replaying one recording twice is EQUAL to itself, so it is neither the input coordinate nor the allocator — suspects are Allegro's WM_ACTIVATEAPP switch-out/in path and the real MOUSE, which --input=real never parks.
- 004 (2026-09-07) carrier limitation, not a divergence: human recording second_human crashed at T≈450 with 'arena exhausted (requested 819200, used 267969472/268435456)' in main_menu_callback — the det-mode heap is a bump-only arena (never frees) and the main menu allocates ~800 KB per frame (create/destroy of a full-screen bitmap), ~40 MB/s. Gameplay allocates little, so scripted runs never hit it. Fix queued: deterministic free-list allocator inside the fixed arena (state lives in arena memory, snapshot-compatible). Workaround: start a game within a few seconds of the menu.
- 004 FIX (2026-09-07, KNOWN by measurement, carrier/NOTES.md 'Divergences 004 and 005'): the bump allocator at 0x20000000 is now an explicit doubly-linked free list, first fit from the head, LIFO insertion, immediate boundary-tag coalescing of both neighbours, plus a bump `top` for never-used bytes. G1/G2/G3 all still EQUAL.

#
# STATUS (2026-09-07, "Allegro inline primitives; .itr workload" pass):
# SOLVED. play() is reached, digest lines appear (157 safepoints, T=394..
# T=550 this run), and assets/log.txt shows "preparing to show replay" ->
# "play started" -> "replay ended after death" -> "play ended". Root cause
# and fix below; carrier/NOTES.md has the full writeup plus the live-trace
# evidence (DET_TRACE_REPLAY_SELECTOR=1, carrier/src/det.cpp) that found it.
#
# ROOT CAUSE (corrects every earlier pass's "debounce counter permanently
# blocks keypressed()" theory - that theory was WRONG, disproved by a live
# breakpoint at _replay_selector's own `call _readkey` site, VA 0x41d671):
# keypressed()/readkey() fire constantly regardless of the counter. The REAL
# problem is entry 0 of the replay browser's own file list is the ".."
# parent-directory entry (MEASURED: cursor=0, is_dir_byte=1, num_itr_files=
# 14 = 13 real .itr files + 1 ".."). A held KEY_ENTER (this script's own
# earlier 360-tick hold, used to confirm "Load Replay" from the main menu)
# triggers Allegro's real keyboard-repeat mechanism, which queues MANY
# repeat keypresses into the SAME buffer _replay_selector later drains one
# read-key at a time - so its very first keypressed() call already finds a
# BACKLOG of queued repeats and "confirms" entry 0 (".. ") over and over,
# each confirm re-scanning a directory ONE LEVEL FURTHER UP the real
# filesystem (MEASURED: num_itr_files climbing 14 -> 2 -> 3 -> 8 -> 23 ->
# 103 -> ... as it walks up past profiles/MissingNO -> profiles ->
# assets -> ... on the real disk) and never landing on a real .itr file.
#
# FIX: every press+release in this script is now the shortest possible
# hold (1 tick) so Allegro's repeat-delay never has a chance to queue a
# second event from the same physical press, plus one extra KEY_DOWN tap
# after opening the browser to move the cursor off the ".." entry (index
# 0) onto the first real file (index 1, MEASURED is_dir_byte=0 there).
# A 20-tick hold (still short of the earlier passes' 360) was tried first
# and still let repeat queue 3-4 events before release - 1 tick is what
# actually worked, MEASURED zero extra CONFIRM hits before release.
#

# --report's binding.functions[].crossings_original_to_form, this run):

# - menu idle polling, not just gameplay), update_particle, fps_counter,
